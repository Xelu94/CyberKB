### T1574.001 — DLL Search Order Hijacking

- **Táctica:** Persistence / Privilege Escalation
- **Contexto:** El nombre `DINPUT8.dll` es una DLL legítima del sistema Windows (DirectInput 8). Si un atacante colocase un fichero con este nombre en el directorio de trabajo de una aplicación, podría intentar que dicha aplicación cargue la DLL falsa en lugar de la del sistema. Con solo 10 bytes, el fichero actual no es funcional como DLL, pero podría representar una prueba de concepto o un artefacto de reconocimiento.

### T1491.002 — Defacement: External Website

- **Táctica:** Impact
- **Contexto:** El nombre `index.php` con contenido mínimo (10 bytes) es consistente con la sustitución de una página de inicio legítima por un placeholder en ataques de defacement web, donde el atacante reemplaza el contenido original con un fichero mínimo o una página de reemplazo.

## Recomendaciones

### Para equipos de respuesta a incidentes (IR)

1. **No escalar este hash como amenaza activa.** La evidencia disponible no justifica clasificarlo como malicioso. El veredicto forense es: **archivo benigno o neutral con alta probabilidad**.

2. **Investigar el contexto de descubrimiento:** Si este hash fue encontrado en un sistema durante una investigación, es fundamental analizar:
   - ¿En qué directorio se encontró el fichero?
   - ¿Qué nombre tenía en el sistema comprometido?
   - ¿Qué proceso lo creó (revisión de logs de creación de ficheros)?
   - Si el nombre era `DINPUT8.dll`, verificar si existe la DLL legítima en `C:\Windows\System32\` y comparar hashes.

3. **Si el fichero fue encontrado como `index.php` en un servidor web:**
   - Comparar con el contenido original del `index.php` legítimo.
   - Revisar logs de acceso del servidor web para detectar actividad anómala antes y después de la modificación.
   - Verificar integridad de otros ficheros PHP del servidor.

4. **Correlación con otros indicadores:** Un fichero de 10 bytes por sí solo rara vez es concluyente. Buscar artefactos adicionales en el sistema: conexiones de red inusuales, procesos no reconocidos, tareas programadas, claves de registro modificadas.

### Para administradores de sistemas

5. **Monitorización de DLLs críticas:** Implementar reglas de detección (Sysmon, EDR) para alertar cuando se cree o modifique un fichero con el nombre `DINPUT8.dll` fuera de `C:\Windows\System32\` o `C:\Windows\SysWOW64\`.

6. **Integridad de aplicaciones web:** Utilizar herramientas de monitorización de integridad de ficheros (FIM) en directorios web para detectar modificaciones no autorizadas de `index.php` u otros ficheros de entrada.

7. **Principio de mínimo privilegio:** Asegurarse de que los procesos de aplicación web no tienen permisos de escritura sobre sus propios directorios de despliegue, reduciendo el riesgo de defacement o implantación de webshells.
